# Domain Docs

This repository uses a single domain context.

Before exploring a change, read:
- `CONTEXT.md`
- relevant records under `docs/adr/`

Use the glossary vocabulary from `CONTEXT.md` in issue titles, specs, tests and design notes. If a term is missing, resolve it through domain modeling before inventing a synonym.

Read relevant ADRs and surface conflicts instead of silently overriding them.

The root `CONTEXT.md` is the glossary and contains no implementation details.
`docs/adr/` contains durable architectural decisions.
