# 去 AI 味

把指定文字改得自然、具体、有人物温度，同时不改变它讲的事。判断标准以 `novel-craft` 的「正文表达 · 去 AI 味」为基线；本技能补充更完整的痕迹词表、力度分档、改写边界和交付前自检。

本技能只改表达。续写、扩写、调整情节或人物关系不属于本技能；作者同时提出这些要求时，先按当前写作流程完成内容任务，再对最终文字执行本流程。

## 1. 确定范围

按以下顺序确定要改的文字，命中一项即停止：

1. 作者在消息里明确指定的对象（段落、章节、文件或粘贴的文字）。
2. 本条消息附带的选中文字。只改选区，选区外的内容一字不动。
3. 当前打开的章节或文档。

对象仍不明确时，先请作者指定。不要自行选择最新章节，也不要扩展到整卷或整部作品。

## 2. 确定力度

| 力度 | 何时使用 | 改动范围 |
| --- | --- | --- |
| 轻度 | 作者说「稍微」「别改太多」「只改最明显的」 | 只处理最扎眼、最密集的痕迹；句子结构基本不动 |
| 适中（默认） | 没有说明力度 | 词表 A–D 组的命中逐处处理；段末升华全部处理；结构问题只改影响阅读的 |
| 大幅 | 作者说「彻底」「整段重写表达」「AI 味很重」 | 在适中基础上处理 E、F 组的句式和结构问题，可以重组句子和段落节奏 |

字数变化是参考而不是硬指标：轻度一般不超过原文的 ±10%，适中 ±15%，大幅 ±25%。明显超出时检查是否在注水或删掉了有效信息。

## 3. 先读证据

- 读取目标文字的当前版本。改工作区文件时用 `read`，不要凭记忆改。
- 读 `CREATOR.md` 中的文风与禁止项。
- 上下文里有 Prose Style References 时，读全局文风参考，以及与本场景明显匹配的场景参考。**作者证据优先于通用规则**：作者稳定使用的口头禅、重复句式、比喻密度、长段说明或习惯词，即使出现在词表里也保留。
- 涉及人物、地名、功法、物品等专有名词时，按需用 `query_lore_items` 核对写法。专有名词一字不改。
- 用 `skill` 工具加载 `novel-craft`（本轮已加载则跳过），只读 `scene-and-payoff.md` 的「正文表达」一节；再读本技能的 `skill://humanize/references/ai-trace-lexicon.md`。`skill` 工具不可用时，直接使用本文件和词表。

## 4. 诊断

逐段标出痕迹，记下所属组别（见词表）。判断时注意：

- **看密度和场合，不看单个词。** 全章出现一次「微微」不是问题；三段内五个「微微」、每个角色都「瞳孔一缩」才是问题。
- **区分叙述和台词。** 人物说话本身就可以带口癖、套话或书面腔，那是人物声音；只有叙述腔混进台词（台词在播报信息、替作者解释）时才改。
- **区分作者习惯和模型痕迹。** 第 3 步读到的作者证据里有的写法，标记为保留。

作者只要求诊断时，到这一步为止：按段落位置列出主要问题、所属组别和建议改法，不修改文件。

## 5. 改写规则

- **情绪标签** →「他感到 / 他意识到 / 心中充满」改成身体反应、注意力落点或下一个决定。三者选最贴合当下处境的一个，不要三个一起堆。
- **万能副词与程度词** → 能删就删；删了站不住时，用一个更具体的动作代替程度。
- **程式化神态** → 换成这个角色在这个处境下才会做的小动作，或者直接删掉神态，让台词自己承担。不同角色不要共用同一套反应。
- **空泛氛围** → 落到场景里已经存在的具体物件、声音、气味或光线上。只能用前后文已经交代或场景里必然存在的东西，不为「具体」而编造新事实。
- **段末与章末升华** → 删掉总结句、感悟句、排比金句；需要收束时，停在本段已经出现的动作、台词或后果上，不新增情节。
- **整齐结构** → 打散三段式排比、成对的「不是……而是……」、等长段落；紧张处用短句，平缓处允许长段。
- **台词播报** → 保留台词的信息和语气，去掉完整回答、背景解释和书面连接词；可以加入试探、回避、打断，但不能改变谁知道什么。
- **翻译腔** → 改成汉语自然语序，去掉多余的「进行」「一个……的」「被……所……」。

改写以句子为单位，尽量保留原句里有效的部分。原句本来就自然的，原样保留：宁可少改，也不要把一种腔调换成另一种腔调，或把书面叙述改成油滑口语。

## 6. 不能改的

- 剧情、事件顺序、因果、结果。
- 人称视角、叙述距离、时态。
- 人物所知：不能让人物多知道或少知道信息。
- 人物关系与称呼。
- 专有名词、硬数字（年龄、时间、金额、距离、人数）。
- 台词的信息量和立场。
- 作者在第 3 步证据中体现的稳定文风。

不要新增事件、角色、对话回合、粗口或网络流行语，不要为了「像真人」凭空添加微动作。

## 7. 写入与核验

- 文字来自聊天（粘贴或「改一段给我看」）时，直接在回复中给出改后的文字，不写文件。
- 作者要求不修改文件、只返回可采纳正文时（例如编辑器选区动作），不要调用 `write` / `edit`；把改后的完整选区放在唯一一个 ` ```manuscript ` 代码块中，说明写在代码块外。代码块里只放正文，不放标注或解释。
- 改工作区文件时，遵循当前写作技能的工具规范：局部修改用 `edit`，`old_string` 必须与当前文件完全一致且唯一，不能带 `read` 返回的行号前缀；改动遍布全文且力度为大幅时，才用 `write` 整体替换。
- 处理选区时，每处 `edit` 的范围都必须落在选区之内。
- 检查每次 `edit` / `write` 的结果；出现 `[tool error]`、`string not found`、匹配不唯一、路径错误或截断提示时，不要声称完成，重新读取目标后修正重试，或明确说明没有写入成功。
- 写入后用 `read` 复核改动处的关键片段。

本技能只改表达，不改变叙事事实，因此不需要更新 `setting/progress.md` 或 `setting/character-states.md`。

## 8. 交付前自检

1. 词表 A–D 组在目标范围内还剩多少处？剩下的是否都是作者习惯或台词需要？
2. 逐段对照原文：事件、人物所知、专有名词、硬数字有没有变化？
3. 是否新增了原文没有的事实、动作或物件？
4. 字数变化是否在本力度的参考范围内？
5. 遮住人名，主要人物的台词还能分辨出是谁说的吗？
6. 段落节奏是否还过于均匀？结尾是否又写成了总结句？

## 9. 输出

- 正常情况下只给一两句说明：改了多少处、主要是哪几类问题、保留了哪些作者习惯。不贴完整诊断报告，除非作者要求。
- 作者要求对照时，按「原句 → 改后」列出主要改动，最多十条。
- 有无法在不改事实的前提下处理的问题（例如整段都在解释设定），说明原因并给出建议，由作者决定是否调整内容。
