# 逐章写作与落盘

1. 读取 `setting/outline.md`，定位当前章的任务、冲突、揭示和钩子。
2. 读取最近一至两章；第一章则读取已确认方案在对话中的内容和必要的 `CREATOR.md`。
3. 先在内部确定本章的进入点、三到五个场景动作和章末变化，不向作者输出写作计划。关键场景要包含“主角当下要什么 → 阻力采取什么动作 → 主角被迫选择 → 立刻出现什么后果”。
4. 创作约 3000～5000 字的章节正文；少于 3000 字视为本章推进不足，应优先补足有效场景、人物回应、选择与后果，不用重复解释凑字。作者指定篇幅时以作者要求为准。
5. 使用 `write_file` 写入自动确定的章节路径。新工作区按现有系统章节命名规则生成第一章；后续沿用已有命名并递增，不询问作者 Markdown 地址，也不硬编码另一套章节格式。
6. 检查工具结果；失败则修正或如实说明。成功后用 `read_file` 读回开头、关键转折或结尾，确认正文实际存在。

正文开头直接叙事，不输出章节标题。默认一轮一章，让作者能在现有 Diff 中审核后再继续。

一章可以包含经营、训练、调查或时间推进，但不能只有过程蒙太奇。至少让一个具体人物或现实限制在场景中回应主角的行动。若删掉阻力后本章结果不变，补足争夺、选择及其代价再落盘。
