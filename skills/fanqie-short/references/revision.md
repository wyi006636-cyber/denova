# 逻辑、常识、动机与对白修改

## 修改顺序

1. 从选区或 `read_file` 得到真实原文，确认修改边界和前后衔接。
2. 用一句内部判断定位问题：因果断裂、信息不足、人物无收益、常识错误、对白同声或节奏拖沓。
3. 只改解决问题所需的最小范围；需要补铺垫时同时修改最近的有效铺垫点，不扩写无关段落。
4. 使用 `edit_file` 写回并检查结果，让现有 Diff 承担接受或拒绝。

## 当作者说“剧情太平”

先读取已确认大纲和作者指出的章节，找出哪一段形成了“主角按计划推进、对手没有回应、胜利没有代价”的直线。若问题跨越多章，先给作者一条推荐的三到五步冲突升级链，逐步写清：谁因主角的行动受损、采取什么合理反制、主角先付出什么代价、哪次选择让其失去退路、高潮必须舍弃什么。可以补充一到两个备选，但不要只列宽泛方向把判断重新丢给作者。等待作者确认后再改大纲或正文。

升级冲突不等于把对手写得更坏、堆事故或突然曝光秘密。只使用正文中已经出场的人物、关系和资源，让既有人物根据自身利益，通过公开署名或否认、合作提案、角色去留、产品或品牌动作作出可见回应，并让下一步压力由上一步选择直接触发。凡是依赖临时出现的第三方机构、事故、合同纠纷或渠道封锁才能成立的节点，删掉重做。保留作者已确认的题材、人物底色和结局方向，只修改造成平直感的最小章节范围。

默认把回复控制在约 700 个汉字内并收敛成四部分，不逐章复述原文：

1. **根因**：用两三句话指出最主要的平直因果链。
2. **推荐升级链**：给出一条三到五步的具体方案，每步写清涉及章节、对手的公开行动、主角选择、代价和下一步压力。
3. **保留项**：列出无需推翻的关键人物、有效场景和结局。
4. **确认问题**：请作者确认这条方案；确认前不调用写入或修改工具。

除非作者明确要求，不改变已经确认的人称或视角，不用切换到对手 POV 解决“告知多、展示少”。优先让对手通过主角可观察的品牌动作、合作提案、人才挽留、价格或资源竞争进入场景。

## 常见修法

- **因果**：补齐“触发 → 选择 → 行动 → 可见后果”，不要用旁白宣布合理。
- **动机**：给人物一个当下收益、恐惧或关系压力，让行动与代价相称。
- **常识**：能确认就改成准确动作；拿不准且细节不影响剧情时，改成稳健的非专业表述，不编造程序或结论。
- **对白**：区分人物的目的、词汇和回避方式；让台词带潜台词，并用动作承接权力变化。
- **连续性**：核对时间、地点、已知信息、伤势、物品和人物位置，只修复已出现的矛盾。
