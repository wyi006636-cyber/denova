# 写法案例库

这本技能只处理写法方法，不把参考原文当成本书事实。参考原文放在 `references/sources/`，案例放在 `setting/cases/`，目录放在 `setting/case-index.md`，拆书进度固定放在 `references/sources/<来源主名>.progress.md`。进度文件是工作检查点，不是参考原文：读取、列出来源和书籍设定扫描都必须排除 `*.progress.md`。不要新建数据库、资料条目或第二套故事事实。

## 一个案例长什么样

文件名与标题第一个词必须相同；编号只使用小写英文、数字和连字符（例如 `c-opening.md` 与 `# c-opening 先给异常`）。字段可以使用下面的中文标签；英文书也可以使用对应英文键和值 `Status: pending|collected`、`Direction`、`Use when`、`Method`、`Do not copy`、`Source`、`Location`、`Quote`、`Prefix`、`Suffix`。

```markdown
# c-opening 先给异常

- 状态：待确认
- 方向：开篇
- 适用场景：章首或新场景
- 方法：先写一个可观察的异常，再让人物采取处理动作。
- 不要搬用：不要复制参考原文的人物、事实、情节或句子。
- 来源：references/sources/example.txt
- 定位：未知
- 原文前文：门外很安静。
- 原文摘录：灯亮了。
- 原文后文：他没有立刻开门。
```

`原文摘录` 必须是来源中的连续原文，最多 120 个 Unicode 字符；摘录重复时必须同时填写 `原文前文` 或 `原文后文` 来消歧。收藏时程序会重新核对摘录并补上真实定位，因此不要相信模型自行填写的行号。

目录 `setting/case-index.md` 只保存检索行，不复制原文：

```markdown
# 写法案例

## 已收藏

- c-collected | 节奏 | 先写异常，再让人物处理

## 待确认

- c-opening | 开篇 | 先写异常，再让人物处理
```

拆完一段必须同时完成三件事：写入 `setting/cases/<编号>.md`，在目录的「待确认」（英文目录可用 `## Pending`）下追加一行 `- <编号> | 方向 | 方法`，更新 `references/sources/<来源主名>.progress.md`；完成后停下来询问作者是否继续。不要只写案例或只写进度。

## 拆一段原文

作者明确指定来源、方向和范围后才开始。先用 `read` 读取 `setting/case-index.md` 和对应的 `references/sources/<来源主名>.progress.md`，再用 `read` 的 `offset`/`limit` 读取需要的原文；不要先读完整本书。一次处理约 8,000–12,000 个汉字，或一个清楚的章节标题范围，以较小者为准。读完后用 `write` 新建或用 `edit` 修改 `setting/cases/<小写英文数字连字符编号>.md`，同时更新目录「待确认」行和进度文件，并停下来询问作者是否继续。

每个案例至少写出方向、适用场景、方法、不要搬用、来源、定位、原文摘录和状态。状态只能先写「待确认」（英文书可写 `pending`）；程序收藏时会再次核对摘录并计算定位行号，不能相信模型自行填写的行号。收藏缺少定位行时程序会补写行号，但新案例仍应按模板写出定位字段。

Agent 不得把状态写成「已收藏」，不得改动目录的「已收藏」节，也不得把原文、人名、地点、情节或原作专名写进 `chapters/`、`setting/lore/`、大纲或写作进度。案例只是写法观察，不是本书世界观。没有对上的摘录留下失败进度，作者说重试这一段时再读原文。

## 写作时怎么用

续写、改稿和普通对话默认不读案例，也不搜索 `references/sources/`。只有作者点名某条案例、明确说按案例写，或在本轮用 `@` 带入案例文件时才读它。使用时只取已收藏案例的方向、适用场景、方法和不要搬用字段；不要把来源路径、定位、原文摘录、原作人物、原作事件或原作专名带进正文、资料库或游戏状态。

「待确认」案例不是可用方法。收藏和取消收藏只能由作者在案例库视图中操作；按钮会以当前 revision 读取案例和目录，并在服务端核对来源摘录后一起更新两个文件。来源不存在、摘录找不到、多处命中或超过 120 个字符时不要改任何文件。

## 目录与进度

`setting/case-index.md` 只保留案例编号、方向和方法的检索行，不复制原文摘录。动态工作区索引只列这个目录的路径，不列 `references/sources/` 正文。原文不要一次用 `@` 带入；需要长文时继续分段 `read`，每段完成后留下进度检查点。
